# Local publishing hooks

Run `bash scripts/install-git-hooks.sh` after cloning on the Mac. This installs repo-local wrappers and preserves any prior hook as a timestamped backup. The wrappers use the versioned scripts here. The existing global hook chain calls them; global Git settings are unchanged. The installer deliberately uses the actual git-dir, not `--git-path hooks` (which follows global `core.hooksPath`).

A clean `main` commit publishes only to this repository's `origin/main`. Other branches, detached HEAD and dirty trees do not auto-publish. The local pre-push guard checks updates to main only: it refuses deletion, non-fast-forward changes, a dirty/mismatched checkout and `SKIP_TESTS=1`. It runs the publish scrub. Quick Launch's tests then run once through the existing global fallback, which discovers the backticked `swift test` command in `CLAUDE.md` (that line is load-bearing); RTI explicitly runs all RTITests plus ChatSourceLifecycleTests and ChatRuntimeIntegrationTests using `.deriveddata-publish`, separate from normal builds. Other pushes retain the global hook's existing behaviour. Pre-commit remains responsible for design lint; never use `--no-verify` to skip it.

A commit waits for verification and publication, which can take several minutes. Git does not undo a commit if post-commit fails: check the output, then compare `git rev-parse HEAD` with `git ls-remote origin refs/heads/main` before claiming publication. A failed publish leaves the commit local. Investigate before retrying through the installed post-commit hook; do not force push. Do not run another build or edit the checkout while publication is being verified.
