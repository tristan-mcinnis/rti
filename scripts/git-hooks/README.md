# Local publishing hooks

Run `bash scripts/install-git-hooks.sh` after cloning on the Mac. This installs repo-local wrappers and preserves any prior hook as a timestamped backup. The wrappers use the versioned scripts here. The existing global hook chain calls them; global Git settings are unchanged. The installer deliberately uses the actual git-dir, not `--git-path hooks` (which follows global `core.hooksPath`).

A clean `main` commit publishes only to this repository's `origin/main`. Other branches, detached HEAD and dirty trees do not auto-publish. The local pre-push guard checks updates to main only: it refuses deletion, non-fast-forward changes, a dirty/mismatched checkout and `SKIP_TESTS=1`. It runs the publish scrub. Quick Launch's tests run once through the unchanged global hook: `.test-command` selects the versioned `test-command` wrapper, which clears inherited repository Git variables and runs `swift test`. RTI explicitly runs all RTITests plus ChatSourceLifecycleTests and ChatRuntimeIntegrationTests, against an exact `git archive` of the commit being pushed, with a private source snapshot and build cache at `~/Library/Caches/com.tristan.rti/publish-tests` outside the TCC-protected Documents folder. Only tracked files are copied; the credential-free `Secrets.swift.example` supplies the compile-time shim, never the live ignored file. Its gate also clears repository Git variables before package resolution. Both post-commit hooks clear those variables before calling Git, so dependency mirror clones cannot be redirected into the app repository. Other pushes retain the global hook's existing behaviour. Pre-commit remains responsible for design lint; never use `--no-verify` to skip it.

A commit waits for verification and publication, which can take several minutes. Git does not undo a commit if post-commit fails: check the output, then compare `git rev-parse HEAD` with `git ls-remote origin refs/heads/main` before claiming publication. A failed publish leaves the commit local. Investigate before retrying through the installed post-commit hook; do not force push. Do not run another build or edit the checkout while publication is being verified.
