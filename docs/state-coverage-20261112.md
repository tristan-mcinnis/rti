# RTI state coverage, 12 November 2026

Three places can lose the user's work even after the local action appears successful. A failed frame move deletes the staged frame. Correcting a mistaken moderator assignment leaves previously captured Guide quotes missing. Finishing a transcript upgrade can clear the retry marker before a failed raw export reaches the downstream meeting processor.

The inventory covers the 236 tracked Swift files under `RTI/Core` and `RTI/Sources` at review revision `0ed8495f`. Core has 99 files in ten directories. Sources has 137 files in twelve directories plus five root files. The map groups files by the state they own. Pure values, protocols and styling helpers are included with their consuming owner. Existing test names below describe coverage in the checkout. Two new headless probes ran for this review. OS events, provider traffic and every possible task interleaving have not been exercised.

[Projection](../RTI/Core/Guide/GuideExtraction.swift) · [live edits](../RTI/Sources/Session/SpeakerNameStore.swift) · [archived edits](../RTI/Sources/Session/SessionArchive.swift)  Preserve evidence keyed to original turn IDs, apply current role during projection and prove undo/reassignment restores the same evidence once. | 6. Failed transcript edits | **Source.** Sessions attempts an atomic write with `try?`, then exits editing and reloads. A failed write can discard a moderator's draft without an error. The archive's speaker editor already retains its state on a write error. | 7. Cross-surface recording status | **Source.** The command socket acknowledges accepted intent before main-actor execution. | 8. Generation and visible control freshness | **Source.** Choosing an assistant provider for a chat updates that thread and the default. Saving Settings updates the default on its own. A streaming turn freezes its selected route. Auto and Notes collapse admission cancellation and provider errors into nil via `collectAsync`; the generic retry message cannot identify which happened. 1. Use the isolated beta with four invented voices, one reconnect, a changed guide question, a moderator correction and two upgrades. Match source turn, displayed identity, quote, marker, archive and raw export at each point.
2. Block one output at a time, restart and retry. Watch actual archive, retry marker, frame and raw-export files independently of the status label. Use an injected processor stub to verify once-only handoff.
3. Exercise real mic/screen/calendar permissions, two displays, ordinary window controls and live backreading with a 60-minute fixture. Observe window geometry and each scroll view separately.
4. Keep stable and beta profiles distinct under normal launch and recovery. Use fixture paths for both in automation. Verify paths, socket/manifest, hotkeys, own-window filtering, destinations and retained chat/record references before the first real test recording.
