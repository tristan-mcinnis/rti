# Research codebook files (schema 2)

RTI reads schema 1 and 2 files and writes schema 2. Each Research recording writes `codebook.json` and `codebook.md` beside its transcript. Selecting a project in an eligible business project root also writes those two files in that project. The archive JSON owns the evidence from one session. The project JSON includes those entries across sessions and owns card identities and moderator edits. Markdown is a readable projection. An older session with none of these files opens normally.

| Field | Meaning |
| --- | --- |
| `schemaVersion`, `projectDirectory` | Schema integer and optional directory of the merged book. |
| `sessions[]` | Stable recording `id`, optional `group`, recording `startedAt` (seconds since 2001-01-01 UTC), archive `folder`, consumed original turn IDs, `endMs` watermark and `incomplete` flag. |
| `cards[]` | UUID `id`, canonical `name` (the respondents' own Chinese words for a theme, need, tension, barrier or emic term), optional English `gloss`, `aliases`, `type`, `origin` (seeded or emerged), `pinned`, append-only `entries`, and optional `qids`, `provenance` (spontaneous, prompted, moderator_introduced), `votes`, `questionStatus` (open, partly answered, answered) and `clientBrand`. |
| `type` | A code: theme, need, emic_term, ritual, trigger, channel, barrier, brand, stimulus_reaction, tension, hypothesis, vote, client_question. Schema 1 files can also hold person, org and concept. They still load. Person and org cards are not codes and are never shown; concept shows as a theme. A pass never creates them, and no new code or seed resolves to one. |
| `votes[]` | One line per choice: `sessionID`, `choice`, `count`, `source` (moderator_tally, respondent_explicit, sticker), `turnID`, `offsetMs`. A later tally of the same choice replaces the count. |
| `entries[]` | `point`, `valence` (positive, negative, mixed, neutral), optional moderator-spoken `inferredName`, and `evidence`. Optional: `excerpt` (exact words from the turn), `strength` (spontaneous, prompted, agreement), `asrDoubt`, `stance` (for or against, hypotheses only) and `counter` (the other side of a tension, a second `evidence`). Within a card, session ID plus turn ID identifies a single entry. |
| `evidence` | `sessionID`, `turnID`, `group`, `offsetMs`, immutable original-language `original`, `speaker` (raw ID, label, Me/Them leg, confidence, optional seat and segment, moderator flag), optional `questionID`, `markerID`, `markerLabel`, `packageRevision`, `showEventID`, `shownItemIDs`, `shownCodes`, and `revealRecorded`. `mentionedCodes` lists neutral material codes literally spoken in the cited turn. `upgradedOffsetMs` locates a unique verified original in the system-leg upgrade. A missing match or a match across a material or marker boundary sets `anchorNeedsReview`. The original offset and words stay available. Missing shown codes means untracked, an empty array means explicitly cleared. Shown identifiers record an exposure. They do not assign a remark to a particular material. |
| `suppressed`, `redirects` | Normalized aliases for dropped cards and source-to-survivor UUIDs from explicit merges and synthesis merges. Replay respects both. |
| `objective` | Optional study objective from a seed line. |

A preparatory seed is one line in Setup or `<project>/codebook-seed.md`. A line can be a name (a theme), a Markdown list item, or `type | canonical name`. `client | name` seeds the client's brand, pinned. `objective | text` sets the objective. `client_question | text` opens a client question. A `person | name` line is ignored, and `org | name` seeds a brand. Heading and blank lines are ignored. The objective, client brand, stimulus codes, guide section titles, client questions and hypotheses form the short brief (600 characters at most) that every codebook call gets. Explicit guide JSON `hypotheses` is an optional array of names. The codebook summary draws from the evidence points on the card.

`quotes.jsonl` contains a `ResearchQuote` evidence object per starred turn. Focus the transcript and press **S**, or use **⌘⌥8** during a Research recording. Clicking a transcript line selects it. With no selection, the shortcut uses the latest finalized turn. A repeat star of the same session/turn has one effect.

The `-rti.md` sidecar names `codebook_json`, `codebook_markdown`, `quote_bank` with absolute archive paths when present, and the two `project_codebook_*` paths when the project merge has succeeded. Session and project files use owner-only, atomic replacement. Each update rereads the file under a cross-process lock. When the project is unavailable, `projectMergePending` is true in the session projection. Retry merge after the project returns to apply the saved entries and reconcile existing aliases.
